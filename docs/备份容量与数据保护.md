# 备份容量与数据保护

## 容量和保护规则

普通公开目录JSON保持50MiB读取限制；完整摄入备份单独采用1GiB字节上限，读写共用限制及严格JSON校验。备份采用暂存、刷新、真实回读和快照校验，成功后才移动为目标文件；已有目标不覆盖。恢复、导入和升级所需前置备份也必须可读，否则停止数据替换。

九类集合沿用当前数量上限（食物、摄入、份量、批次、身体、目标、锻炼各10万，餐次1000，模板1000）。新增写入在同一个SQLite事务中核对数量和保守的JSON字节预算：每个持久化字符按最多6字节转义、每行保留4096字节固定字段空间，并加上快照头部空间。该预算比实际文件严格，确保新接受的数据可以进入1GiB备份；数量上限与字节预算同时满足才可增长。删除标记计入备份数量。

达到数量上限仍可修改已有ID；已有超限数据允许不增加超限数量和总预算的修改及删除。独立SQLite数据库归档入口不受JSON数量/字节限制，用SQLite一致性备份和完整性检查保护旧库；程序提供显式命令行和设置页入口。超限库不得通过删数据才能获得保全副本，不将数据库归档伪称JSON完整恢复文件。

数据库归档恢复方式：程序关闭后，保留现有数据目录，将归档复制至新的独立目录并命名为journal.db，使用匹配程序的--data-dir打开；不直接覆盖正在使用的库。升级前原始数据库归档在JSON验证失败时依然保留，并显示路径。跨版旧程序的原读取上限保持事实，不声称旧版能读新版的大文件备份。
