# 表格记录与输入清空

用途：记录用户2026-10-23新增要求的1.13.0设计、阶段和验收。状态：2026-10-24正式源码83项、140查询、432项WPF布局（含表格48项）、桌面、程序包、旧结构1–7升级及8→7→8全部通过；发布结果统一见开发进度。保留1.12及全部旧稳定完整包；后续顺序按已批准的新路线图V2，自动备份优先于菜谱。

## 范围与操作

- R36：所有采用应用文本框样式的可编辑输入框，在有内容时显示一键清空按钮；只清当前输入，不删除数据库记录，触发绑定、计算、搜索及未保存保护，支持撤销。空、只读、禁用输入不显示可用清空按钮。按钮有中文提示，不增加常规Tab焦点。
- R37：“设置与数据”移到主导航最后，身体记录、统计、目标与锻炼在其前面；按页面职责刷新，测试同步新导航顺序。
- R38：在设置中选择“现有表单”或“表格记录”，默认现有表单。保存后切换并在重启保留；设置草稿不直接切换。有任一摄入草稿时，要求先保存或取消再切换；切换主导航保留各自草稿。
- R39：新页按日期倒序、每日期按餐次分组，支持滚轮、最近30天、区间及继续加载，最多366天。每天包含启用餐次和有历史数据的停用餐次，日期及餐次标题明确分界。每餐“新增一行”只增加本机内存草稿，默认设置决定重量模式。多行可并存，逐行保存、取消；修改已存行、删除有确认。保存前不计入合计，未记录与零区分。
- R40：行内名称输入联想个人食物库（中文、英文、别名），明确选择候选才带入食物、状态、单位热量/原始kJ、蛋白质及来源。输入名称本身不自动关联、不联网；未选择候选允许手动填写。修改已关联名称须解除旧关联且保留用户已填数值，来源明确标为手动。候选支持键盘与鼠标、无匹配及清空。
- R41：行内支持g/kg、每100克大卡或kJ、单位蛋白质、本项能量/蛋白质，复用既有Core计算与校验；点击本项热量切到直接模式。展开区提供日期、餐次、时间、状态、备注、来源、改为手动及可食重量/份量换算；模板沿用独立整餐核对入口。每行保留历史快照，编辑不按当前库重算，移动日期/餐次后归入正确分组。食物入库询问/自动/不加入策略沿用既有事务。

## 数据与实现边界

`JournalSettings`新增可空`DailyRecordPage`（null为现有表单，`sheet`为表格），空值不写JSON，旧恢复点原序列化保持。数据库及备份升为8，结构7以前的备份不得夹带新设置。升级前备份，旧设置自动采用现有表单。九类资料及新设置一并完整恢复。草稿不属于已保存资料，关闭前确认放弃，恢复/隐藏草稿前明确阻止；不创建虚假零摄入。

界面增加独立表格UserControl及行编辑模型，计算调用Nutrition/WeightCalculator，写入调用JournalService和现有食物入库策略。输入清空使用共享TextBox模板与路由命令，保留绑定和撤销。表格横向滚动，操作/名称列固定，其他字段明确单位；每餐表格有合理高度并可滚动，日期列表虚拟化，不复制10万条数据库到每个输入候选。
