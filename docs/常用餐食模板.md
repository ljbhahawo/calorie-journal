# 常用餐食模板

用途：记录I3 / 1.8.0的R21设计、数据影响及T30验收。状态：2026-10-23已完成正式本地验收；1.7完整归档保留。实际测试、发布状态及边界见[开发进度](progress.md)和[验证摘要](版本归档/1.8.0.json)，总体顺序见[后续功能开发计划](后续功能开发计划.md)。

## 用户流程

每日页面增加“餐食模板”入口，打开独立窗口，沿用现有中文样式。管理页可查询、新增、修改、删除模板；模板有名称、多项个人库食物、各自可食重量或用户定义份量、可选默认餐次及备注。保存模板不产生摄入。添加食物使用当前个人库的中文/别名搜索；食物不存在时先维护食物库，不自动寻找同名条目替代。

选择模板并点击带入后进入整餐核对，采用主窗所选日期，可更改日期及启用餐次；各项允许修改重量/份数、重新选食物/份量及取消选择，也可追加食物。核对显示各项大卡和合计，明确保存整餐才一次产生多条摄入。取消不写摄入。模板管理中的明确保存单独生效。

每次明确带入生成一个批次ID，核对页保存成功后禁止再次提交；数据库持久记录批次，重复提交同一批次必须拒绝，不能重复追加。主动重新带入形成新批次，允许用户真实吃了两次相同餐食。删除或修改摄入不解除原批次的重复保护。

## 数值与引用规则

模板保存引用ID及必要的名称、状态、单位热量、来源、重量与份量快照，便于维护时显示原内容；带入核对时按明确引用ID读取当前有效食物和份量，重新计算未来这次摄入，提示核对更新后的数值。已经保存的摄入完全沿用自身快照，不由模板、食物或份量的后续修改重算。

食物已删除、份量已删除或不属于该食物时，带入明确指出问题，要求在模板编辑中重新选择，不静默忽略某项。默认餐次停用时核对页要求选择启用餐次。按g/kg输入最终可食重量，或按份数调用已有WeightCalculator，沿用0.1g、3位份数和0.1大卡规则；每模板及整餐1–100项。

Core负责模板校验、引用检查、批次生成与计算；界面不写SQL和热量公式。整餐保存使用一个真实SQLite事务，事务内复核食物/餐次和批次ID，写入失败不能留下部分条目或成功批次标记。

## 数据与回滚

数据库3增加模板表和已保存批次表，完整备份3包含模板、批次、份量和完整摄入。旧结构1/2迁移前保存相应版本可读取的数据库、JSON完整备份和校验说明，事务失败保留原结构。新程序可以明确恢复旧备份，旧格式缺少的模板和批次为空；恢复前完整归档当前新版数据。旧版1.7看到结构3须拒绝写入。

模板删除保留标记，快照中的食物引用允许指向已删除但保留的条目，加载时要求重新选择。批次保留其原条目ID清单；用户以后删除其中摄入不构成损坏引用，重复保护仍有效。备份检查模板/批次ID唯一性、食物和餐次引用、各项精度及依据，未知格式不能静默读取。

返回1.7需要选择结构2恢复点，先完整归档结构3的模板、批次、份量及摄入，再用1.7暂存恢复并原子替换工作数据库。旧工作视图只反映恢复点，后来的记录和新类型数据完整保存在新版归档；返回1.8并显式恢复归档后须逐项一致。演练只使用独立测试目录。

## T30与实施顺序

1. 实现模型、边界校验和计算；真实SQLite验证多食物模板维护、重量/份量、引用失效和当前值更新，历史不变。
2. 实现事务批次与持久重复保护；真实写入故障必须回退全部条目及批次，同批重复不得增加记录，明确新批次可保存。
3. 迁移及完整备份包含所有新数据；实际1.7修改/删除状态、份量及历史快照迁移保留；无效备份、备份失败、事务故障和旧版拒绝均有证据。
4. 实现管理与整餐核对界面，真实WPF和实际桌面完成新增/编辑模板、部分调整、取消、整组保存、重复保护和重启回读，最小窗口及四档缩放可达。
5. 独立源码锁定重建、核心回归、自包含包和结构3→2→3完整恢复通过；逐项比较模板、批次、份量、食物、餐次及摄入后才标记稳定、提交推送和发布。未完成迭代不替代1.7。
