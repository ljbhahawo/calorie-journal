# 历史记录导入设计

用途：规定1.3文字导入的范围、处理规则和验收。状态：2026-10-22已实现并交付1.3.0，实际证据见[开发进度](progress.md)；1.2.0完整保留为回滚版本。

## 已确认范围

用户提供了日期标题、餐次合计、食物分项、约数、区间、下限及修正数值混排的文字；随后明确本版先完成文字和从Excel复制的表格，直接读取Excel、图片和PDF留待后续。本版完全离线，不接入网络识别服务，不保存用户原始饮食资料到源码、测试报告或公开包。

入口设在“设置与数据”，打开独立导入窗口。步骤为粘贴原文、选择格式与缺省年份、生成草稿、编辑并选择记录、校验、确认导入。预览不写数据库。文字格式支持明确日期和餐次标题；表格使用首行列名识别日期、餐次、名称、大卡及可选时间、备注，支持制表符和CSV。列名不认识时明确提示修改首行，不能猜列。

## 处理规则

- 无年份的月日使用界面明确显示的缺省年份，默认本机当年；完整日期保留原年份。未来日期、缺少日期和不明确餐次必须修改或取消选择。
- 早上/中午/晚上映射早餐/午餐/晚餐；“上午”“下午”和未标餐次不自动推断。预览允许选择当前启用餐次；需要新增餐次时先在设置添加。
- 餐次合计与明细同时出现时，合计保留为参考，默认选择明细；可改为采用合计，但同一天同餐的合计与明细不得同时导入。原文仅有合计时允许作为一条“餐次合计”记录；不会虚构食物或拆分热量。
- 区间、下限默认不填确定值。用户可选择下限/中值/上限，或手动填写；仅有下限时不能生成中值或上限。保留原区间和估算说明。
- 有明确大卡单位、尾部热量或“约”数值时生成候选；多处热量取末项供核对并标注，重量与数量不能直接当热量。只支持明确的加法表达式，不执行任意公式或脚本。
- 明确的“无”可生成零热量合计，空白或未知内容不能填零。无法完整识别的片段保留为待核对行，缺少热量的行须补齐或取消选择。
- 所有导入条目采用原记录热量快照，不按现食物库重新估算；来源保存解析规则版本、批次标识、行号和原文，不保存来源文件的私有绝对路径。
- 同一原文、格式、年份和行位置产生稳定ID，已导入行默认排除且禁止覆盖。不同来源但日期、餐次、名称、时间及热量相同的行标为疑似重复；用户明确允许后才可追加。
- 确认前再次校验全部选择；先导出完整“导入前”备份，再在单个SQLite事务中追加。不覆盖既有条目，不更新食物库和餐次；失败全部撤销本批写入。备份失败则不开始写入。
- 数据库、备份、食物包版本保持1，与1.2.0兼容。恢复导入前备份会恢复到该时间点，之后的数据先由现有恢复流程另行归档，不宣称自动合并。

## 开发阶段与T24验收

1. 解析与业务：完成原文到草稿、表格解析、日期/单位/歧义提示、合计防重叠、重复检查和事务追加。用明确的验收输入测试，真实私人原文只在项目忽略目录做检查。
2. 窗口与集成：可编辑预览、选择范围数值、餐次对应、确认和备份；主页面刷新及未保存编辑保护。实际完成粘贴→修改→校验→导入→历史核对；取消和无效输入不能改库。
3. 验证与交付：真实SQLite回归、事务中途失败、导入前备份及恢复、重复导入拒绝；真实WPF绑定/辅助技术/最小窗口/缩放，独立源码重建和程序包检查；实际1.3→1.2.0→1.3往返保留导入快照，旧包不变。

单次原文限制20万字符、草稿最多1000行；超出时明确终止，不悄悄截断。无法覆盖所有自然语言表达时保留原文与待核对状态，不承诺任意格式自动正确识别。
