# 测试与验收

用途：定义首版及后续迭代必须验证的行为及证据。状态：2026-10-22 已执行核心自动化、独立WPF绑定与焦点布局、150%系统DPI下桌面交互、自包含候选包和候选往返回滚；修正后复验通过。详细证据见 [桌面验收记录](桌面验收记录.md) 和 [开发进度](progress.md)。

## 验证原则

自动化检查运行真实Core与SQLite实现；测试目录在项目`workspace/`，不使用实际用户数据库。确定性输入用于验证数学和操作行为，明确属于测试输入，不作为真实饮食或食物来源数据。内置食物数值验证使用其真实公开来源。若需要规模数据或故障注入，先说明方式，未经授权不加入mock或伪造数据替代集成验证。

UI实际操作检查另行记录；只有代码与数据库测试通过不能证明界面可用。不能仅凭进程存在断言所有页面通过；工具无法验证时保留限制。

## 阶段和发布标准

- 每阶段执行相关单元、集成与最小运行检查，保存实际命令、结果和对应版本；失败后修复并重验相关部分。
- 初版验证从无数据库到首版结构的迁移；后续每个数据库版本增加上一正式版到新版的升级测试，不声称提前验证尚不存在的未来版本。
- 首版交付要求所有核心功能检查通过，没有已知导致计算错误、记录丢失或恢复失败的问题。界面与打包未实际验证时不得标记完整验收。
- 若无法提供无预装运行时的Windows环境，自包含发布包可在本机独立目录运行，但“干净机器验证”单独标为未执行及其影响。
- 检查文档链接、实际命令、发布包与数据版本；已知限制写入README与进度。未运行的检查保留原因和下一步。
- 新功能进入稳定版前执行T19和T20；回滚只在项目隔离测试数据上演练。数据备份损坏、版本不兼容、当前归档失败或仍有写入实例时，回滚必须停止并保留现状。
