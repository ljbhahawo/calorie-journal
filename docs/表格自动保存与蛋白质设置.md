# 表格自动保存与蛋白质设置

状态：1.15.0实施设计，2026-10-24。依据用户最新要求，优先于后续扩展计划；验收结果统一记录在[开发进度](progress.md)。

## 范围和交互

- 表格首列食物名称，第二列本项大卡，二者固定，横向滚动不遮挡大卡。重量、单位能量及直接能量依次排列，统一48像素行高和单个输入区域；操作位于最后。蛋白质列按当前模式填写每100克或本项g，选中行的详情显示计算后的本项蛋白质，防止两行内容挤在单元格内。
- 普通回车保存所在行，Ctrl+Enter继续可用。备注内回车保留换行；候选列表及展开的选择框优先完成选择，不误保存。点击窗口内当前行以外的区域，先尝试保存当前已修改的行，再执行点击目标。
- 未填写的空行不自动写入；不完整或无效输入显示原因并保留草稿，不能当作零摄入。保存失败阻止本次切换，不能重复写入。关闭窗口仍可明确选择放弃草稿。
- 操作列保留“保存”作为明确入口；原“取消”改为空行“移除空行”、填写后的新行“放弃新增”、已存行“放弃修改”，说明仅处理当前未保存内容；有修改时仍确认。
- 设置提供“每日记录显示并录入蛋白质”，默认开启，控制表格、原表单、每日列表和汇总。食物资料库保留营养来源供核对。关闭后新增摄入不填入蛋白质，历史数据不删除；编辑已有重量记录沿用原单位蛋白质并正确计算。已有蛋白质的记录改变录入方式、名称或来源须先开启核对，避免隐式丢失或错误沿用快照。模板新增摄入也遵循开关，模板自身资料保留。

## 数据保护

表格行采用标准可视虚拟化，日期外层继续复用容器。实测.NET 10.0.13在回收表格行、组合框变更并向辅助功能树发送事件时，会因空数据项抛出异常；标准模式仍只生成可见行，但不复用已断开的行容器。保留UI Automation并验证首末行反复滚动和枚举，未重新声称验证大规模视觉帧率。模式含义见[Microsoft官方定义](https://learn.microsoft.com/en-us/dotnet/api/system.windows.controls.virtualizationmode?view=windowsdesktop-10.0)。

新增可选`JournalSettings.ProteinEnabled`，缺失表示开启；设置进入完整备份。数据库和备份升至9，迁移前归档原8。旧版不能直接写入9；返回1.14须选择升级前8恢复点，先完整归档9，返回新版时恢复该归档。旧恢复点之后的新记录及开关在旧版不可见，但归档不得丢失。不改变九类业务资料或公开食物资料、依赖。

## 验收

1. 920×600及100/125/150/200%布局下，不滚动即可看到名称和本项大卡，操作列最后，单行输入和按钮可达；kJ统一预览为大卡。
2. 真实WPF和桌面分别验证回车、点击行外、同一行继续填写、候选选择、备注换行、已存行编辑、空行、明确零、验证错误、实际SQLite写入失败、入库询问取消及重复回车。
3. 开关保存、重启、备份恢复及9→8→9验证；新重量/直接/模板摄入不记录蛋白质，已有营养快照保持，重新开启可见，不能以隐藏列冒充数据保护。
4. 完整回归、独立源码锁定重建、自包含包真实启动、升级回退和公开附件校验通过后才标稳定，保留1.14及全部旧包。无法验证的环境独立注明。
