# 千焦换算与蛋白质记录

用途：记录1.12.0新增能量单位、直接录入切换及蛋白质的需求、数据影响和验收。状态：2026-10-23已完成正式本地验收，1.11.0及全部旧稳定包保留。用户本次新增要求优先，原菜谱及后续计划顺延；实际证据及发布状态见[开发进度](progress.md)和[验证摘要](版本归档/1.12.0.json)。

## 功能与计算

R33：食物库每100克热量、摄入按重量的每100克热量和直接录入本项热量均可选择“大卡”或“kJ”，默认大卡。界面清楚标注按每100克还是本项。输出及统计统一为大卡；1大卡=4.184kJ，依据[NIST SP811换算表](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b8)的thermochemical kilocalorie。保留原始kJ输入（最多两位小数），按原始值及重量计算后最终保留一位大卡，不能先将每100克转换值舍入再乘重量。每100克大卡仍保留两位、直接大卡仍最多一位；单位切换显示同一能量的换算值并提示核对，加载历史或食物时保留原始单位。只对克进行重量计算，不把毫升自动当克。

R34：用户点击或键盘进入直接热量输入框时取消按重量模式，可立即保存有效直接输入；不修改设置默认值。编辑/复制历史、食物带入、换算及模板仍保持对应模式和快照。模式切换取消不再适用的重量依据，直接模式不提交隐藏的重量/单位蛋白质字段。

R35：食物库新增可选每100克蛋白质（g，0–100，最多两位小数）；摄入可按重量自动计算或直接填写本项蛋白质（g，0–100000，最多两位小数）。按重量保存当时的单位蛋白质及结果，最后舍入至0.01g；未知为null，明确0为0。食物修改、删除、目录升级不重算历史。模板与常用份量按实际可食重量携带当前蛋白质和原始kJ依据，整餐核对及保存保持一致。新资料询问入库包括蛋白质和原始kJ信息，查重不丢失新字段。

食物表、参考查询、摄入明细及按餐/连续列表展示蛋白质；每日及分餐汇总只合计已填写项，注明未填写条数，全部缺失不显示0。直接热量与蛋白质分别输入，不用蛋白质反推总能量。旧摄入没有蛋白质时保留未知，不能从当前食物回填过去。

官方参考蛋白质与热量保持同一来源ID、版本及加工状态。USDA使用原档nutrient 1003（Protein/G），TFDA使用原档对应蛋白质分析行；缺失保留未知，不根据食物名称猜测。使用独立补充目录并核对原档哈希，保留原始热量文件及中文索引哈希。主动TFDA更新时解析同档蛋白质，不混用旧档补充值；旧缓存可缺失。现有用户修改和删除食物保持，升级只为未修改内置项补充有来源的蛋白质，旧历史仍未知。

## 存储、阶段与验收

数据库/备份升为7。FoodItem新增可空每100克原始kJ和蛋白质；IntakeEntry新增原始kJ、单位蛋白质及本项蛋白质快照；模板明细携带相同单位字段。新增SQLite可空列，旧结构按版本读取，迁移前完整备份。旧备份1–6禁止夹带新字段，格式7校验所有计算及空值组合；九类集合及设置一并备份恢复。

1. Core计算、模型、SQLite7、旧格式兼容及官方蛋白质补充生成：验证4.184关系、重量舍入临界、范围/精度、缺失/零、直接与重量模式、历史快照、模板、备份和真实事务失败。
2. WPF表单及单位/模式事件：真实点击和键盘进入直接框可保存；编辑复制保留原单位/数值；食物维护、参考资料带入、重量换算、模板及汇总正确；最小920×600及四档布局入口可用。
3. 实际桌面、正式源码锁定重建、自包含程序、真实旧结构1–6升级及失败保护；7→6→7安全回退使用明确1.11结构6恢复点，先完整归档新字段与全部资料。旧版不显示kJ原值、蛋白质和恢复点后记录，返回新版可恢复，不自动合并旧版期间数据。
4. 全部验收后提交推送、附注标签、公开新版与1.11完整回滚包及校验清单；保留全部旧版本。未完成迭代不替代1.11稳定版，不执行菜谱功能。
