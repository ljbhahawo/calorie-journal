# 使用说明

用途：说明本机运行、摄入记录、身体记录、目标和锻炼、营养数据、备份及版本恢复。涵盖1.0至开发中的1.14；使用稳定版时以其随包说明为准，当前交付状态见开发进度。

## 表单定位、搜索和身体趋势（1.14）

每日表单标明必填/选填。保存时缺少必填项会显示原因并滚动聚焦第一个缺失字段；重量模式填写重量与每100克能量，直接模式填写本项能量，零须明确输入0。搜索个人食物库可输入中文、别名和英文，按Down进入候选、Enter引用、Escape取消，也可鼠标点击；输入搜索词本身不会替换草稿。清空按钮在输入区域上下居中，保留撤销。

身体记录可切换“测量明细”和“体重与腰围趋势”，沿用已应用查询区间。体重kg与腰围cm分别缩放；圆点是已保存的实际测量，连线不代表额外测量，日期按真实间隔显示。腰围缺失处断线，空值不当零，指向测量点可查看日期/数值。请结合带单位的纵轴和原明细核对，未增加预测或摄入建议。

1.14回滚入口按目标程序清单的备份容量检查，历史清单未声明能力时仍为50MiB；不能因为当前程序支持1GiB就向不支持的旧程序强行恢复。结构同为8，可直接切换1.14/1.13并保留当前全部资料；显式选择旧快照时仍先归档，再确认恢复时间点。

## 表格记录与清空（1.13）

主导航最后的“设置与数据 → 每日记录页面”可选择“现有表单”或“表格记录”，点击保存录入设置后生效并保留到下次启动。切换前请保存或取消摄入草稿；修改其他设置不会改写已填写的记录。

表格按日期、餐次分组。点击对应餐的“新增一行”，填写名称、重量与每100克能量，或直接填写本项能量；可选择大卡/kJ，蛋白质可留空。名称输入会下拉显示个人热量库的中文、别名或英文匹配，选择后带入状态、单位营养及来源，填写名称本身不自动关联。USDA/TFDA参考资料仍通过食物库的查询入口核对加入。每行分别保存或取消，Ctrl+Enter可提交当前行；新增空行和未保存修改不计入小计。

点击本项直接能量框会取消重量模式。展开行下方的详情可修改日期、餐次、时间、状态、备注，使用可食重量/常用份量、转为手动来源或删除已保存记录；模板仍通过独立核对窗口操作。横向滚动查看其他字段，保存与名称列固定；上下滚动浏览不同餐次和日期。默认最近30天，可选区间或加载更早，最多366天；关闭和恢复前保护尚未保存的行。

可编辑文本框有内容时显示“×”清空按钮，只清当前输入；支持撤销/重做，并更新搜索、预览及草稿状态。只读、禁用和空输入不提供清空操作。

## 大备份与数据库保全（1.13）

1.13随包回滚脚本的显式快照入口仍会拒绝大于50MiB的文件，拒绝时保留当前资料；应用和CLI恢复采用1GiB限制。使用大归档时可关闭程序，将归档保留并通过匹配程序的`--data-dir <新的独立目录> --restore-backup <归档> --confirm-restore`恢复到新目录核对，不能直接覆盖原目录。下一维护版本会统一脚本与目标程序能力，当前不宣称该脚本支持大文件往返。

完整JSON备份单独支持最大1GiB；写出后会重新读取并校验，校验完成前不视为成功。数量上限及保守的转义字节预算共同约束新增资料；达到上限仍可编辑已有资料，旧超限库允许不扩大超限范围的修改和删除。普通公开目录JSON保持50MiB限制。实际验证规模及内存/耗时范围见开发进度，不把1GiB声明视为所有机器的性能保证。

“设置与数据 → 保存数据库归档”使用SQLite一致性备份和完整性检查，适用于JSON容量或数量超过限制的旧库。它保存独立`.db`，不覆盖现有文件。命令行同样支持：

```powershell
.\app\CalorieJournal.exe --data-dir "数据目录" --export-database "新的归档路径.db"
```

数据库归档不能在JSON恢复对话框中打开。恢复时先退出所有相关程序，保留现有数据目录，将归档复制到新的独立目录并命名`journal.db`，用匹配版本的`--data-dir "新的独立目录"`打开；不要覆盖正在使用的库。该入口在升级前即可保全旧数据库，不要求先迁移成功。

数据库/备份8包含页面选项及原九类资料。返回1.12必须指定结构7旧恢复点，回退前完整归档当前资料；旧工作视图不显示旧点之后的记录，返回新版可恢复归档。旧程序仍有自身的备份读取限制，超大新版JSON不能宣称可直接由旧版恢复，也不自动合并旧版期间新数据。

## 千焦与蛋白质（1.12）

食物库的每100克能量、记录中的每100克能量和直接输入本项热量旁均有“大卡/kJ”选择。照营养成分表填写正确的每100克或本项数值；不要将每份或每100毫升的数值直接当作每100克。1大卡=4.184kJ，结果、合计和目标比较统一显示大卡。kJ最多两位小数，原值随历史保存，按原值计算后才舍入最终大卡，避免每100克中间舍入误差。单位切换会换算显示值，请核对显示精度。

点击或键盘进入直接输入热量框会取消“按重量计算热量”，可以直接保存本项热量。此操作只更改当前草稿，设置里的新建默认录入方式不变。编辑、复制、模板和食物带入继续保留对应计算依据。

食物库可填写每100克蛋白质g（0–100，最多两位小数）。选择食物或手动填写单位蛋白质后，按实际可食重量计算本项蛋白质；直接录入则填写本项蛋白质g（0–100000，最多两位）。蛋白质可留空，空值显示未填写，明确输入0显示0.00g。摄入明细、按餐和连续列表展示保存时的蛋白质，每日/分餐合计注明未填写项数，不把不完整合计当成完整摄入。食物后续修改不重算历史，模板保存的摄入同样保留快照。

USDA蛋白质来自同版原档1003 Protein/G，7793项均有值；TFDA同档粗蛋白/g有2183项、30项缺失。参考结果保留来源编号及说明，可带入食物表单；旧缓存版本不同不混用补充值。主动TFDA更新解析同档蛋白质，并写入独立`tfda-protein-v1.json`缓存，旧版缓存不被覆盖。未修改内置食物可补充蛋白质，用户修改/删除项不改，旧摄入不回填蛋白质。

数据库及备份格式升为7。回到1.11需选择升级前结构6恢复点，先完整归档当前资料；旧版不显示原始kJ、蛋白质或恢复点后的新记录。返回1.12可通过安全入口恢复完整归档；旧版期间新增记录不自动合并。不要直接让旧程序写结构7。阶段验收和限制见开发进度。

## 自设目标与锻炼（1.11）

在“目标与锻炼 → 摄入目标”输入每日大卡、生效日期和可选备注后保存。目标可预设未来日期，同一天只能有一条；新增调整保留更早目标，持续至下一条生效日前一天。勾选“从生效日起暂停目标”可以结束目标比较。数值须为0.1–99999.9大卡，最多一位小数，由你设置。

右侧显示各条生效起止日期。日常调整使用新增记录；修正或删除已有条目会改变该日期区间的历史目标比较，程序会要求确认。摄入记录本身不变。选择比较日期后点击“查看比较”；每日记录也显示当天目标及差值。未设目标、已暂停或当天未记录摄入时不计算差值；实际录入0大卡时按零值比较，不能据此判断当天是否完整记账。

在“锻炼记录”填写日期、活动和分钟，消耗大卡及备注可选。时长0.1–1440分钟，消耗0–99999.9大卡，均最多一位小数；空消耗显示“未填写”，明确零显示0.0。可选择记录后修改或删除，同一活动可记录多次。默认最近30天，可查询最多366天；未保存的草稿在取消、切换编辑或关闭时受确认保护。

运动消耗只单独记录，不抵扣摄入、不增加目标额度。汇总只加总已填写的消耗，并列出未填写次数；不根据活动名称估算能耗。

1.11数据库和完整备份格式为6，包含目标与锻炼。升级前自动在数据目录`recovery`生成旧结构数据库及旧版可读JSON；保留1.10完整包。回到1.10须退出程序，使用安全回滚入口明确选择升级前的结构5恢复点，先完整归档当前结构6资料。旧版只能显示该恢复点已有资料，目标、锻炼及此后新增记录在新版归档中保留。重新启用1.11时，通过安全入口恢复回滚前结构6归档；旧版期间新增内容不自动合并。恢复旧备份会清空其中未含的新类型，界面会预览数量及影响；不要只复制旧exe写入结构6。

## 启动和数据位置

将完整Windows x64压缩包解压到自己的文件夹，双击`app/CalorieJournal.exe`。程序包含.NET运行时，无需安装Python、SDK或数据库服务器。不要从压缩包内部直接运行，也不要只复制exe而遗漏其他文件。

首次运行初始化60项基础食物与早餐、午餐、晚餐、加餐，摄入列表为空。默认数据目录为`%LOCALAPPDATA%\CalorieJournal`，可在“设置与数据”查看；更换程序目录不会迁移该数据。同一数据目录只允许一个程序实例写入。

可使用命令行指定独立目录，目录含空格时加双引号：

```powershell
# 工作目录：解压后的程序目录
.\app\CalorieJournal.exe --data-dir "E:\个人记录\热量数据"
```

## 日常记录

在“每日记录”选择日期与餐次。可以直接填写食物名称和本项大卡；也可以搜索食物，选择准确生熟状态后填写重量，程序按每100克大卡计算。重量单位支持g和kg。

保存后表单清空，便于添加下一项；当日列表显示每条记录、分餐小计和合计。1.2将保存与“新建 / 取消”固定在左侧卡片底部，字段区可独立滚动；选中明细后点击“修改记录”或“删除记录”。编辑时加载保存当时的食物数值，主动重新选择食物才带入食物库当前数据。

空日期显示“未记录”；1.2历史表中对应热量显示横线，实际记录0大卡时继续显示0.0及已记录状态。软件合计只反映已录入内容，不判断是否漏记。可在“历史查询”选择日期范围，再进入当天明细。列表字段较多时可左右滚动。

选择一条历史明细后点击“复制到今天”（1.1称“复制为今天的新记录”），保留当时的食物、重量、单位热量和备注，日期改为今天、时间清空。核对表单并点击保存才产生新记录，原记录不变。原食物删除后仍可复制其快照；原餐次停用时需要核对当前启用餐次。复制不会自动套用食物库更新后的热量。

## 录入偏好与按餐浏览（1.8.1）

1.8.1在“设置与数据”中可保存默认录入方式和新资料入库方式。新建默认按可食重量及每100克热量计算；可取消默认重量选项，之后的新建采用直接输入大卡。设置不改写当前草稿、历史和复制的方式。“还原已保存设置”只撤销尚未保存的偏好修改。

新手动食物的入库方式有“每次询问、自动加入、不加入”，默认每次询问。询问中的“是”同时保存新食物和摄入，“否”只保存摄入，“取消”保留草稿、不写入。自动加入也须包含有效单位热量；只有本项总大卡时不猜算每100克资料，仍可保存摄入并提示补充。相同名称、状态和单位热量不重复加入，不同状态或单位热量可独立保存；不会覆盖已有资料或复活删除项。较长来源在食物说明中注明节选，完整说明保留在摄入快照。

每日页面点击“按餐”，早餐、午餐、晚餐和加餐分别显示标题、小计、明细；自定义餐次独立展示，停用但当天有记录的餐次仍可查看。使用鼠标滚轮浏览，点击“添加本餐”填写左侧表单，或点击某条“修改/删除”；总量、各餐、连续列表及历史同步更新。总量只保留紧凑合计，主要高度供摄入明细使用。

1.8.1使用数据库4/备份4，录入设置进入完整备份。返回1.8.0须选结构3恢复点，先归档全部当前数据；旧版只展示恢复点，返回1.8.1并恢复新版归档才能找回后来的摄入和设置。较早格式恢复后采用默认录入设置，恢复前仍完整归档当前数据。各版实际验收见开发进度。

## 餐食模板（1.8）

保存或取消主窗正在编辑的内容后，点击“餐食模板 · 整餐核对”。在“模板管理”填写名称、可选默认餐次和备注，通过顶部个人食物库搜索选择食物，再点击“增加食物”。每项填写可食重量，单位可选g、kg；已有常用份量时选择份量、单位改为“份”，填写实际份数。需要维护份量时先返回主窗使用“换算可食重量 / 常用份量”。模板管理支持名称搜索、修改、删除；点击“保存模板”仅保存组合，不增加摄入。

点击“带入整餐核对”，程序按引用ID读取当前食物和份量资料；请核对日期、餐次、每项重量或份数及总大卡。可以取消某项的“记录”勾选、增减草稿食物或更换所选食物，调整只影响本次。食物或份量已删除时明确提示，需重新选择，不自动套用同名条目。没有默认餐次时必须选择本次餐次。

点击“保存整餐摄入”后全部所选项在同一事务写入，失败不会留下部分记录；保存成功后锁定本批，连续点击不能重复增加。再次真实吃相同组合时返回管理页重新点击“带入整餐核对”，形成独立新批。关闭未保存核对不写摄入。模板、食物、份量后续变化均不重算既有摄入。

1.8使用数据库3和完整备份3，包含模板和保存批次。升级1.7前自动保存旧结构数据库、JSON备份及校验说明。返回1.7须使用完整旧程序包及结构2恢复点，先归档所有当前新版数据；1.7只展示旧恢复点内容，后来新增摄入、模板和批次保存在新版归档，返回1.8并恢复该归档才能全部展示。不要直接用旧exe打开新版数据库。演练与限制见[版本迭代与回滚](版本迭代与回滚.md)。

## 周/月统计与趋势（1.10）

进入“摄入统计”，默认本周（周一开始）。选择按周/按月及其中一天后点击查询，可切换上一/下一周或月；“当前”返回当前周期。自定义区间最多366天，填写起止日期后查询。当前周期只统计至今天，未来日期不参与。日期筛选无效时保留此前有效统计。

已记录总量只累加已录入资料，平均仅除以有记录天数，不判断某天是否完整记账。未记录日显示“—/未记录”，不计入平均；保存了0大卡记录的日期显示0.0，并计为一个已记录日。全区间未记录时总量和平均显示未记录。

每日趋势按日期递增，正值为绿色柱，真实零为基线绿色圆点，未记录为空缺和“—”；不补零或插值。柱高从0起，刻度按本区间最大值，悬停可看完整日期/数值；长区间可水平滚动。日表提供精确数值和条目数，选中后点击“查看所选日期”返回每日记录；未保存表单仍需确认。最小窗口可纵向滚动统计页，图表和日表均保留空间。

数据库/备份仍为5。1.10与1.9可通过完整程序包切换并保留当前全部数据；显式恢复旧快照时先归档，返回新版可恢复归档，身体资料和设置一并保留。

开发者可运行`./scripts/Clean-LocalArtifacts.ps1`预览，确认范围后加`-Apply`清理本地重复产物。稳定完整ZIP始终保留，里面包含程序、源码、锁文件和回滚入口；旧版展开目录删除后可从对应ZIP重新解压。含数据文件、活动程序或不同内容的目录受到保护；源数据、测试报告、验证数据、恢复点和依赖环境保留。

## 身体记录与层级浏览（1.9）

每日“按餐”使用餐次标题、引导线及缩进的食物明细；“连续列表”分为日期→餐次→食物三层，日期和餐次各有独立背景、小计，不只用颜色区分。原添加、修改、删除与滚轮操作保留。

进入“身体记录”，填写测量日期和体重kg，可选填写身高cm、当时年龄、代谢公式男/女选项、腰围及备注。体重最多两位小数，身高和腰围最多一位；每天一条，已有日期请在右侧选择记录后点击“修改身体记录”。核对预览后保存，列表和当前查询区间的最新值、首末实际测量变化同步更新。查询默认最近90天，可修改起止日期；没有测量的日期不填零。新建可带入最近一次身高/年龄/公式选项，请核对当时资料；修改新记录不会更新旧记录的输入。

BMI=体重kg÷身高m²，只显示数值，不做地区、成人/儿童分类。基础代谢参考使用Mifflin–St Jeor 1990简化静息方程：10×体重kg+6.25×身高cm−5×年龄，男公式加5、女公式减161，单位为大卡/日。缺少资料、年龄不在原研究19–78岁或结果非正时明确未估算，仍可保存体重。它是静息能量估算，不是实测结果或每日摄入目标；不会改变摄入合计，也不直接衡量体脂。公式来源：[CDC](https://www.cdc.gov/growth-chart-training/hcp/using-bmi/calculating-bmi.html)、[Mifflin论文摘要](https://pubmed.ncbi.nlm.nih.gov/2305711/)。

1.9数据库5/备份5包含身体记录。返回1.8.1须选结构4恢复点，先完整归档当前全部数据；旧版不能展示新增身体记录，后来摄入和测量保留在新版归档，返回1.9后恢复该归档。旧格式1–4恢复后身体列表为空，恢复前的完整归档继续保留。使用包内安全回滚入口，不只复制旧exe打开新版库。

## 连续列表（1.4）

在“每日记录”右侧点击“连续列表”，按日期倒序查看每天的合计、餐次和食物明细。在列表上使用鼠标滚轮浏览，默认显示最近30天；可以查询指定日期区间，或点击底部“加载更早30天”，最多连续显示366天。更早的记录可通过调整查询区间查看。

点击某天右侧的“添加”，左侧表单自动使用该日期；点击某条明细的“修改”，左侧加载保存时的完整内容。核对并点击“保存摄入”后，列表、单日和历史合计同步更新，较早日期的保存保留列表滚动位置。修改日期时可将摄入移到另一天；新日期超出当前查询区间时，状态栏提示调整区间。点击明细的“删除”须确认，只删除该条摄入。

切换“单日 / 连续列表”会保留未保存表单。开始另一条新增或修改、有效日期切换时仍须确认是否放弃草稿；无效未来日期先被拒绝，不弹弃稿提示，今天的“后一天”按钮不可用。未记录日期和实际0.0大卡继续分开显示。

## 可食重量与常用份量（1.7）

选择食物，或填写手动名称、勾选“按重量计算热量”并填写每100克大卡，然后点击“换算可食重量 / 常用份量”。总重扣除模式填写总重，逐行输入皮、壳、骨等名称及重量，每项可用g或kg。核对最终可食重量及大卡后点击“带入可食重量”，返回主窗保存摄入。扣重超过总重或最终重量为零时拒绝带入。

使用份量时，先在主窗选择具体食物，在换算窗口勾选“使用常用份量”，点击“管理当前食物的份量”，明确填写“一勺/一碗/一个”等名称及实际每份克数并保存；关闭维护窗口，选择份量、输入份数，再带入。每份克数由你称量设置，程序不推测大小或密度。份数最多3位小数，最终克数四舍五入到0.1g，再计算热量。

取消换算不修改摄入草稿；已明确保存的份量定义保持保存。带入后仍须保存摄入，重复打开或取消不会自动新增记录。历史保存当时的总重/扣重或份量名称、每份克数和份数，修改或删除份量不重算历史；“保存时的历史值”仅在主动重新选择后使用新定义。手动修改主表单重量、单位或退出重量模式，会取消此前换算依据并提示。

## 食物库和餐次

“食物热量库”支持中文名称、别名、分类和英文原名查询。选中食物可以维护名称、单位热量、状态及来源说明，也可以新增独立条目。单位热量按每100克填写；1.7支持用户定义具体食物每份克数，毫升和未知大小不能自动换算。

内置数据来自USDA SR Legacy 2018-04，不表示当前某品牌或某道菜的检测值。对应原名、来源编号和加工状态保留，逐项数值及公开档案校验信息随包存放在`app/data/sources.json`。按实际包装补充自建食物时，可在来源说明记录品牌与标签。修改或删除食物不会重算已有摄入。

在“设置与数据”选择或新增餐次、设置显示顺序和启用状态。可增加上午加餐、下午茶或夜宵。停用后仍可查看历史；历史保留当时的餐次名称。

## 查找热量资料（1.5）

在“食物热量库”点击“查找热量资料”，输入中文或英文名称并搜索；可选择全部来源、USDA或TFDA。每个来源最多显示100项，可增加关键词缩小范围。USDA目录有7793项，1.6增加全目录中文食材与状态词描述；TFDA目录有2213项中文食物。不同来源的结果分别列出，数值按每100克可食部分表示。

1.6支持常用别名、简繁、全半角、多词和无空格组合，例如“马铃薯 生”“洋芋 白色”“去皮鸡脯生”。个人食物库采用相同规则，自己维护的名称和别名保持不变。中文是本项目整理的检索辅助，少数品牌和地方食名保留原文限定；结果同时展示完整英文或原始名称，请核对生熟、部位与品牌。地区别名按具体食物区分，例如“马铃薯”不会因TFDA花生的俗名“土豆”而匹配花生；直接搜索“土豆”仍可看到该地区原始俗名相关结果。

选择结果后，下方显示原名、加工状态、编号、版本、获取时间及授权说明。“查看原始网页”打开默认浏览器；TFDA链接为官方资料集页面，须结合整合编号核对。资料获取时间不代表营养检测日期。

点击“带入新增食物”返回左侧表单，核对中文名称、加工状态和单位热量后点击“保存食物”，才加入个人食物库。原始名称及来源继续保留。英文原文较长时，按提示缩短可编辑的名称或加工状态；不修改原名。食物可继续编辑、删除和用于按重量记录，历史保留来源和数值快照。

普通搜索使用随包或已下载目录，无需联网。主动点击“联网更新TFDA资料”才下载官方公开压缩包（当前约4.6MB），校验成功后替换本机参考缓存并重新查询；不上传查询词、食物库或摄入记录。可取消更新或直接关闭窗口，失败会显示原因并保留原资料。缓存损坏时可点击“使用随包资料”明确使用初始快照。USDA SR Legacy为2018年最终目录，不作为在线更新目录。

参考目录与个人食物库独立；查询和更新不会自动新增或覆盖个人食物。缓存位于数据目录`lookup/`，不纳入个人完整备份；已经保存的食物及其来源正常纳入备份。1.6保持数据库1、备份1和TFDA缓存格式；按兼容回滚流程返回1.5.0时新增食物和当前摄入仍可使用。中文索引随独立程序版本保留，回退后检索能力以该版为准。

## 导入旧记录（1.3）

在“设置与数据”点击“导入历史记录”，粘贴自由文字或从Excel复制的表格。选择格式及缺省年份，再生成草稿；没有写入记录前可以返回修改原文并重新生成。复制表格第一行使用“日期、餐次、名称、大卡”，列顺序不限，可另含时间和备注；CSV中的引号、逗号和多行内容由标准解析库处理。

核对页默认选择明细，餐次合计保留作参考。可以逐行勾选，或使用“优先选择合计”，但同一天同餐不能把合计与明细叠加。区间及“以上”等下限不自动填确定值：选中行后取下限、中值、上限，或双击“大卡”单元格填写估计值。没有上限时不能取中值或上限。

“上午”“下午”或未标餐次需对应到现有启用餐次；可先回到设置添加餐次再重新导入。展开下方区域查看选中行原文和提示。所有数值均来自旧记录，不自动用食物库猜测缺失热量；无法识别的行须补齐或取消选择。

点击“校验所选记录”，处理状态列的问题。疑似重复默认阻止追加；同一原文行禁止重复导入。确认已核对后点击“备份并导入”，程序先保存“导入前”完整备份，再一次性追加所选条目；失败不会部分写入。窗口显示成功后关闭，即可在每日和历史页面查看。导入前未保存的编辑需要先处理。

直接选择Excel文件、图片和PDF识别尚未实现；本版使用粘贴文字。详细规则见[历史记录导入](历史记录导入.md)。

## 完整备份与恢复

在“设置与数据”导出`*.calorie-backup.json`，使用新的文件名保存。1.7使用格式2，包含全部摄入及换算依据、常用份量、餐次、食物及用户删除标记，不包含程序本体。请将重要备份保存在自己选择的独立位置。可以明确恢复旧格式1备份，恢复后份量为空，当前份量和记录先保存在恢复前归档中；确认信息会说明这一影响。

恢复先校验文件并显示备份时间与条目数，经确认后替换当前工作数据；原有数据先自动备份到数据目录的`recovery/`。校验失败或前置备份失败时停止恢复。恢复旧备份后，工作视图对应旧时间点，之后的数据保留在恢复前备份中；当前没有自动合并两份备份的功能。

程序亦提供维护命令，正常操作优先使用界面：

```powershell
# 导出到尚不存在的新文件
.\app\CalorieJournal.exe --data-dir "E:\个人记录\热量数据" --export-backup "E:\个人记录\备份.calorie-backup.json"

# 显式确认全量恢复，先保存当前数据
.\app\CalorieJournal.exe --data-dir "E:\个人记录\热量数据" --restore-backup "E:\个人记录\备份.calorie-backup.json" --confirm-restore
```

维护操作非零退出码表示失败；诊断文件`startup-error.json`留在指定数据目录。不要忽略失败后直接继续更换数据库。

## 程序更新和版本回滚

升级前先使用旧版导出完整备份，确认导出成功，再关闭旧版。新版本解压到独立目录，保留上一版完整目录和备份。每个版本包含程序、`source.zip`源码、`manifest.json`校验与数据版本、`回滚版本.ps1`和本说明。版本号含`rc`的是候选版；稳定状态和实际验证范围以对应版本清单及发布记录为准。

在当前版本目录用PowerShell运行回滚入口，先关闭正在运行的应用：

```powershell
# 先预览，不改变数据
.\回滚版本.ps1 -TargetReleaseDirectory "E:\软件\每日热量记录_上一版本" -DataDirectory "E:\个人记录\热量数据" -WhatIf

# 执行时会说明操作并请求确认，先完整归档当前数据
.\回滚版本.ps1 -TargetReleaseDirectory "E:\软件\每日热量记录_上一版本" -DataDirectory "E:\个人记录\热量数据"
```

数据结构兼容时保留当前记录，切换程序版本。若旧版不兼容当前结构，必须另行指定旧版可读取的完整备份：增加`-SnapshotPath "备份完整路径"`；入口会说明恢复时间点，先归档新版数据，再安全恢复。旧版界面可能无法显示升级后的新增记录，但其归档保留，可重新使用匹配新版恢复。回滚期间新增数据不自动并入其他备份。

1.7将数据库升级到结构2。首次打开结构1数据库前，自动在数据目录`recovery/`保存“升级前_结构1”的数据库、可由1.6恢复的完整格式1备份和校验说明；备份失败停止升级。相同版本和食物包的再次启动不重复改写数据库。

返回1.6必须指定升级前的格式1备份，不能直接让旧程序打开结构2。回滚入口先归档当前格式2数据，再由1.6在独立目录校验恢复旧备份，成功后替换工作数据库。旧视图回到所选备份时间点；其后新增的摄入、份量及换算依据保存在新版归档。重新使用1.7时，可显式恢复版本指针记录的新版`RecoveryBackup`；回退期间另有记录时先导出保留，软件不自动合并。

回滚成功后可以使用随包的`启动软件.ps1 -DataDirectory "数据目录"`，它读取该数据目录的版本指针。移动或删除被选中的程序目录后，需要重新指定可用版本。PowerShell若受本机组织策略限制，应由使用者按自己的策略处理；软件不修改全局执行策略。

## 表格快速记录与蛋白质设置

每日表格将名称与本项大卡固定在前两列，横向滚动时仍可核对总量；操作在最右侧。填写后按回车或点击窗口内行外区域保存，保存失败保留当前草稿并提示原因；备注内回车换行，Ctrl+Enter提交。空行不会自动写入。新行“放弃新增”丢弃该草稿，“放弃修改”恢复该行已保存内容，删除已保存记录仍在展开详情中另行确认。

设置与数据中的“每日记录显示并录入蛋白质”默认开启。关闭后隐藏每日页面的蛋白质输入、列与合计，新增表单、表格和模板摄入不填入蛋白质；食物资料库与历史快照保留。历史重量编辑仍按原单位蛋白质计算；更换已有营养记录的食物或录入方式前请开启并核对资料。开关保存后重启和完整恢复仍有效。

1.15使用结构/备份9，升级前自动保存结构8恢复点。回退1.14须关闭程序、指定明确的格式8完整备份；入口先归档全部9资料，再恢复所选时间点。该时间点之后的新增记录及蛋白质开关在旧版不可见，返回1.15可恢复所存9归档。两版期间的新增数据不自动合并，分别导出保留。
