# 开发计划

用途：管理从需求到维护的可交付阶段。状态：2026-10-23 已补充后续功能规划；所有阶段按依赖推进，不以预计耗时作为完成证据。当前状态只在 [开发进度](progress.md) 维护。

## 阶段与验收

| 阶段 | 前置条件 | 工作与交付物 | 阶段验收 |
|---|---|---|---|
| P0 规划评审 | 用户初始需求 | 工作区检查、需求、架构、食物数据方案、决策与验收文档 | 用户确认关键技术方案和内置库起始范围；文档一致、链接有效，范围可执行 |
| P1 工程基础 | P0完成 | 项目隔离.NET 10 SDK、固定版本与依赖、三个生产项目及测试项目、最小窗口、数据路径配置、构建入口 | 实际还原依赖、构建、启动；独立测试目录可写；不修改其他项目环境 |
| P2 数据与食物库 | P1完成 | 版本化数据库、精确热量计算、审核后的内置包、食物增删改查、餐次管理、来源显示 | 真实SQLite持久化与重启检查；数据逐项可追溯；修改/删除不被再次初始化覆盖；计算边界检查通过 |
| P3 日常记录闭环 | P2完成 | 两种手动录入和食物引用、分项增删改、历史快照、每日页面、区间历史与汇总 | 真实操作完成录入→编辑→查看历史→重启；加餐与分餐汇总正确；修改食物不改历史；空日期语义正确 |
| P4 数据保护与升级 | P3完成 | 完整备份恢复、确认与失败提示、迁移框架及首版迁移、单实例、升级数据兼容验证 | 备份回读一致；损坏备份被拒绝；真实事务失败保留旧数据；升级保留用户修改和删除标记 |
| P5 全面验收与交付 | P4完成 | 自动化测试、界面与性能检查、发布包、源码快照、使用/构建与恢复说明、依赖和来源声明、校验清单 | R01–R11对应检查完成；首版稳定归档可启动；数据目录独立；未验证项明确，不把阻塞标完成 |
| P6 授权后的持续迭代 | 首版全部验收完成且有可用额度 | 优先质量改进，再按实际需要选择简洁的锻炼、减脂管理或菜谱功能；每次一个版本 | 新增功能验收、核心回归、程序与数据升级/回滚演练均通过；上一稳定版完整保留 |

P2和P3产物为阶段结果；MVP完整验收在P5结束时完成，食物库、备份和更新保护不能以“后续再补”从当前范围中移除。

## 实施顺序和记录规则

1. P0完成前不安装依赖或编写产品代码；确认后先建立可以真实构建的开发基础。
2. P2先定义计算和快照规则，再实现持久化及食物库；P3在已验证的数据模型上实现用户流程。
3. P4使用独立测试库验证恢复和升级，不能对实际用户数据库执行破坏性测试。
4. P5按 [测试与验收](测试与验收.md) 逐项记录实际执行、结果、环境和产物。错误修复后重跑受影响检查。
5. 每阶段结束更新`progress.md`，记录实现项、变更文件、验证证据、限制和下一步；计划与事实分开。
6. 若需求变化，先更新需求编号、对应设计及验收项目；已授权的后续功能自行选择并记录，超出授权的重大平台、数据来源或范围变化先征求用户意见。
