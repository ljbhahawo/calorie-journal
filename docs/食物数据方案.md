# 食物数据方案

用途：确保内置热量库具有可追溯的数值、清楚的适用范围和可维护的更新方式。状态：2026-10-22 已完成60项USDA SR Legacy基础食物数据包，原名与数值逐项核对；生成入口及实际校验信息保留。

## 1. 数据来源和起始范围

使用USDA FoodData Central的可下载数据，首批整理至少50项常见基础食物，提供中文名称、英文原名和中文别名。覆盖谷物主食、蛋奶、肉鱼、蔬菜、水果、豆类、坚果和油脂等类别；生熟状态不同的条目分开，不能通过改名冒充某种地方菜。

官方主页说明数据采用CC0；下载页提供CSV与JSON，包含Foundation Foods和SR Legacy等类型。SR Legacy标明2018年最终版本，不能标为最新检测值。规划阶段只核对了主页和下载页；具体下载档案、字段、数值和中文映射将在数据实施阶段逐条核对。[来源与许可说明](https://fdc.nal.usda.gov/)、[官方数据下载](https://fdc.nal.usda.gov/download-datasets/)（核对日期：2026-10-21）。

优先选择单一明确版本形成首个包；根据覆盖需求选择Foundation Foods或SR Legacy中的可追溯条目。采用多个数据类型时，每项保留各自类型和版本，不把同名食物视为等价。

当前实际选用SR Legacy 2018-04，数据包版本`usda-sr-2018-04.zh.1`。`data/food-selections.json`保存60项中文选择与精确英文原名，`scripts/prepare_foods.py`从官方CSV逐项提取营养素1008（Energy，KCAL），生成`data/builtin/foods.json`及逐项来源`data/builtin/sources.json`。压缩档案URL、SHA256和实际生成时间均在来源清单中；未将SR Legacy标为最新营养检测数据。

用户于2026-10-22确认50项为首版最低覆盖数量。起始库用于常见基础食物，具体条目在上述类别内自主选择并审核；用户可以根据商品包装和实际饮食新增条目。大量中国菜品或本地品牌食品不属于当前首版覆盖要求。

## 2. 每项数据要求

| 内容 | 要求 |
|---|---|
| 身份 | 稳定内置键、来源FDC ID、数据类型、原始食物名称 |
| 中文显示 | 准确中文名称、可检索别名、分类；不得省略原文中的生熟、去皮、含糖等影响理解的区别 |
| 数值 | 来源能量值、原始单位、标准化后的kcal/100g、具体能量字段标识 |
| 可追溯性 | 来源网址、数据版本、检索日期、数据包SHA256、转换说明 |
| 用户改动 | 自建/内置/用户修改标记；编辑后保留来源说明，显示其数值已由用户调整 |

输入档案使用标准JSON或CSV库解析。能量字段的营养素ID、单位和计量基准依据对应数据说明核实；多个能量字段不能相加；缺失或基准不清的条目不能导入成零。中文翻译作为应用附加元数据保存，不改写原文。

## 3. 数据准备与审核步骤

1. 在项目`workspace/`下载必要的官方档案与字段说明，记录URL、版本、校验值和实际日期。
2. 确认能量字段和每100克计量基础，选取覆盖清单；明确各项可食部分及加工状态。
3. 生成标准化数据包与逐项来源清单，使用固定比例的整数存储单位热量；按公开原始值计算，不添加推测值。
4. 检查ID重复、空名称、缺失值、单位、范围、中文与原名一致性；逐条回查来源数值。保存可重复的转换入口和审核结果。
5. 验证首次初始化可重复执行且不重复导入，能离线搜索引用，并验证用户修改或删除在重启与包升级后保留。

原始公开档案属于开发证据，整理后的可分发包与来源清单进入`data/builtin/`。开发下载与运行时分离，软件正常记录不联网、不需要API密钥。

## 4. 用户使用边界

录入界面明确显示“每100克大卡”和食物状态。缺少重量时不自动使用“一份”假定；只有克/千克换算，不推测毫升密度。用户可按包装标识填写每100克大卡，并注明品牌或来源。

历史摄入保存来源和热量快照；食物库改动只影响之后主动选择该食物的新记录。具体数据保存与升级规则见 [架构设计](architecture.md)。

## 5. 多来源参考目录（1.5）

个人食物库起始60项及原包版本不变。新增独立目录`data/lookup/usda.json`（7793项）及`tfda.json`（2213项），只在用户选择并保存时引用至个人库。USDA取全部有营养素1008值的SR Legacy条目，沿用原60项中文映射，其余保留完整英文名称；原始能量值写入说明，显示值按两位小数四舍五入。

TFDA取官方JSON的“熱量”且单位kcal，明确每100克含量，保留整合编号、原始样品名及加工描述。修正热量单独属于其他分析项，不混入目录。`scripts/prepare_lookup.py`生成随包目录并记录原档SHA256和下载文件时间；联网更新使用同一字段规则、流式读取和版本校验。许可和机构署名见[第三方说明](第三方说明.md)，设计及T26见[热量资料查询](热量资料查询.md)。
