# 运行与验证

用途：提供开发者可以重复执行的构建、测试和本地打包步骤。所有示例工作目录为`E:\codex\calorie-journal`，使用PowerShell 7；只更改当前进程环境及本项目文件，不修改全局配置。普通用户运行方法见 [使用说明](使用说明.md)。

## 工程结构

生产代码位于`src/CalorieJournal.Core`、`src/CalorieJournal.Infrastructure`、`src/CalorieJournal.Desktop`，分别承担规则与接口、SQLite及文件存储、WPF界面。测试位于`tests/CalorieJournal.Tests`及`tests/CalorieJournal.Desktop.Tests`；后者是带真实应用消息循环的独立STA检查程序。

食物选择和中文映射在`data/food-selections.json`，生成的食物包与逐项来源在`data/builtin/`。`scripts/`管理项目环境、生成数据、测试、打包和发布验证；`workspace/`与`artifacts/`包含忽略管理的中间文件及产物。

## 环境与构建

```powershell
Set-Location E:\codex\calorie-journal
.\scripts\Initialize-Environment.ps1
.\scripts\dotnet.ps1 restore .\CalorieJournal.slnx --locked-mode
.\scripts\dotnet.ps1 build .\CalorieJournal.slnx --no-restore '-m:1' '-p:UseSharedCompilation=false'
```

首次准备SDK及还原NuGet依赖需要网络。SDK固定10.0.402，下载后核对官方SHA512；`global.json`固定版本，包版本由各项目及`packages.lock.json`记录。后续升级依赖应更新并复核锁文件，不静默改动全局SDK或其他项目环境。

当前环境的沙箱限制测试宿主的进程通信，首次VSTest连接超时；在环境审批允许本地进程通信后，同一真实测试正常运行。不能通过增加超时将通信受限冒充测试通过。

## 测试

```powershell
.\scripts\Test-Project.ps1
```

脚本设置`CALORIE_TEST_ROOT`为本项目`workspace/tests`。先运行15项MSTest业务/真实SQLite集成测试，再运行独立STA程序中的同一组WPF控件绑定断言；后者使用真实业务和SQLite，不替换实现，不向用户桌面注入输入。任一部分失败都使脚本失败，WPF检查有30秒运行上限。

通用VSTest宿主中曾出现WPF Dispatcher等待。已将绑定检查放入独立STA应用消息循环，实际断言全部保留并通过；挂起诊断记录保留，不能把旧宿主的中止报告记为成功。检查还包括已显示窗口中的焦点导航、最小920×600布局以及100%、125%、150%、200%布局缩放的48项关键按钮访问；不替代系统文件对话框和真实桌面操作。实际桌面验收见 [桌面验收记录](桌面验收记录.md)。

TRX保存在`artifacts/test-results/`，独立绑定检查的结果与阶段记录保存在`workspace/tests/`。独立启动检查：

```powershell
$env:DOTNET_ROOT = 'E:\codex\calorie-journal\.tools\dotnet'
.\src\CalorieJournal.Desktop\bin\Debug\net10.0-windows\CalorieJournal.exe --data-dir E:\codex\calorie-journal\workspace\manual-startup --startup-check
```

图形进程应通过`Start-Process -PassThru -Wait`取得退出码；仅在命令行调用后返回提示符不等于应用完成。成功时写入指定目录的`startup-check.json`，失败时写入`startup-error.json`。

## 食物包重新生成

将官方`FoodData_Central_sr_legacy_food_csv_2018-04.zip`解压到`workspace/usda-sr/`，保留与下载档案一致的子目录名；压缩包本体置于`workspace/downloads/`。使用Python 3标准库即可生成：

```powershell
py -3 .\scripts\prepare_foods.py
```

脚本逐项核对原名、稳定ID、能量字段、单位、精度、范围和重复条目，再生成60项数据与来源清单；不依赖全局科研Conda环境。当前机器实际使用`C:\Python313\python.exe`完成该步骤。重新生成会更新来源清单的实际生成时间，食物ID及原始数值不改变。

## 候选版打包与检查

```powershell
.\scripts\Publish-Release.ps1 -ReleaseVersion 1.0.0-rc.2
.\scripts\Verify-Release.ps1 -ReleaseVersion 1.0.0-rc.2
.\scripts\Verify-Rollback.ps1
# 指定另一组已保留版本
.\scripts\Verify-Rollback.ps1 -OldVersion 1.0.0-rc.2 -NewVersion 1.0.0-rc.3
```

每个新版本目录必须不存在，脚本不覆盖已归档版本。发布需要还原win-x64运行时；产物为包含运行时的完整目录、源码ZIP、第三方许可、SHA256清单、启动及回滚入口，再生成完整程序压缩包。默认标记为candidate，不能把构建成功自动视为稳定交付。

验证脚本在带中文和空格的独立目录解压，核对全部清单，令外部DOTNET_ROOT指向不存在位置，实际运行图形程序与维护命令，检查启动、完整备份恢复、非法备份拒绝及兼容回滚入口。报告写入`artifacts/test-results/release_<version>.json`。两版之间的往返回滚另行记录，不将同版本入口检查当成跨版本演练。

回滚验证脚本使用已保留的rc.1和rc.2及独立测试库，实际执行候选版往返、指定快照恢复、回滚前新数据归档再恢复、无关版本指针拒绝；结果位于`artifacts/test-results/cross-candidate-rollback.json`。只有结构1的两个候选包已经验证，不代表所有未来数据结构均可直接回退。

稳定版本要求实际桌面交互、必要回归与候选包检查完成，再显式使用`Publish-Release.ps1 -ReleaseVersion 1.0.0 -Stability stable`生成新目录，随后运行同一发布包验证。脚本默认candidate，不自动把构建成功标为稳定；版本目录不允许覆盖。首版没有更早正式版，其后每个版本必须对实际上一稳定版执行往返回滚。
