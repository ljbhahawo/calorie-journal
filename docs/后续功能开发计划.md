# 后续功能开发计划

用途：将用户2026-10-23确认的后续功能转为可实施、可验收的版本计划。状态：I1–I3主体已验收，1.8远程发布状态见开发进度；下一优先项为I3a录入设置与当日浏览改进，再继续I4–I7。实际进度和未验证边界统一记录在[开发进度](progress.md)，需求编号见[需求说明](requirements.md)。

## 1. 范围与执行原则

用户接受此前推荐的可食重量与常用份量、常用餐食模板、周/月统计、个人目标及身体测量、菜谱计算、自动备份与表格导出，并新增应用图标及USDA中文和常用别名搜索要求。锻炼记录沿用已有授权，安排在个人记录阶段，保持简洁。

继续采用C#、WPF、.NET 10与SQLite，不增加账户、云同步或后台服务。普通命名、页面布局和兼容实现细节自主决定；新增付费资源、扩大网络用途或重大技术路线变化仍需必要确认。每个阶段开始前核对当前代码、需求、数据影响和验收条目；先修复已确认的质量问题，再按下表实施。

## 2. I1：中文搜索与应用图标

### R18 / T27：USDA中文及常用别名搜索

当前USDA参考目录7793项，仅起始60项具有中文映射；TFDA目录2213项具有原始中文名称。新功能面向整个参考目录及个人食物库，不能只增加少量示例后声称全部支持中文。

1. 单独维护可追溯的中文名称、食材词、状态词和常用别名数据，关联原来源编号；中文索引版本与营养数据版本分别记录。USDA英文原名、来源编号、数值、单位、版本及原始链接保持可核对。中文译名明确属于本软件整理，不冒充USDA官方中文名称。
2. 中文索引覆盖基础食物及其加工状态、部位和常见组合描述。支持土豆/马铃薯、西红柿/番茄、洋白菜/卷心菜、牛油果/鳄梨、鸡胸/鸡胸肉等常用表达。别名对应食材，再结合生熟、带皮/去皮、含糖等条件筛选；小番茄等具体品种不能被当成所有番茄的精确同义词。
3. 统一处理简繁、全半角、英文大小写、空格及多个关键词；优先显示名称和别名准确匹配，再展示相关候选。中文食材加状态词可组合搜索；保留英文搜索能力。不同来源、部位和加工状态分别展示，不合并或平均热量。
4. 参考结果展示中文描述、英文原名、状态、每100克大卡及来源；带入食物表单后保留全部来源信息。个人库按中文、别名和英文原名检索，用户自己维护的名称与别名不能被资料更新覆盖。
5. 中文名称与别名随程序离线提供，支持确定的增量资料更新；不上传私人查询、摄入或食物库。资料整理使用公开食物名称和已有授权工具；不能为翻译静默接入付费或新增远程服务。无法可靠确定的翻译记录为待核对，不编造别名或改变营养数据。

验收T27：

- 对整个USDA目录输出逐项中文覆盖审计，记录可用中文名称/索引、未覆盖项及原因；目标是每项都有可检索的中文食物描述，不能用单一类别名称、非空字段或原60项覆盖率代替该检查。未完成项如实保留为未完成，不能宣布全目录中文支持完成。
- 建立至少100个有预期来源编号和状态的中文/常用别名查询案例，覆盖谷物、蔬果、肉蛋奶、豆类、油脂、调味与加工食品；查询依据来自真实目录及已审核的词表，不在测试中伪造来源结果。
- 检查准确匹配优先、组合关键词、简繁及无结果，核对误匹配；分别验证参考目录和个人库，常用查询无需输入英文。记录真实目录数量和实际搜索耗时，沿用本机搜索300毫秒目标。
- 实际桌面完成中文别名搜索USDA → 核对英文与来源 → 带入 → 明确保存 → 重启回读；中文整理或营养目录更新均不改写已保存摄入快照。
- 校验来源ID、英文原名、营养数值和版本没有因中文整理被替换；保留中文词表来源、整理规则、审查状态和版本，能够复现索引。

### R19 / T28：应用图标

采用简洁的餐盘或叶片元素，沿用现有绿色风格，小尺寸不加入难辨认的文字。生成原创图像，保留原始设计文件与透明背景PNG，再导出包含16、24、32、48、64、128、256像素的ICO；不把位图包装成声称可编辑的矢量文件。

接入可执行文件、WPF窗口及任务栏所需资源；图标、生成方式和必要来源说明进入源码和发布包。实施时使用可用的图像生成工具，并遵守对应技能说明。

验收T28：检查每档尺寸、透明边缘、浅深背景可辨识度；在Windows 11实际核对文件、窗口标题栏、任务栏图标及完整解压后的程序启动。图标资源不得引用本机绝对路径，旧程序包保持不变。

## 3. I2：可食重量与常用份量

R20：提供“总重－不可食重量＝可食重量”的计算方式，可输入皮、壳、骨等扣除重量；支持用户为某一具体食物定义“一勺/一份/一个”等名称和对应克数。每份克数必须由用户明确设置，不能推断个头、容积或密度。录入页显示最终克数和大卡，核对后保存。

实施设计、结构2/备份2迁移及跨结构回退检查见[可食重量与常用份量](可食重量与常用份量.md)，实施状态以开发进度为准。

Core负责十进制换算和边界校验；份量定义进入持久化与完整备份；摄入快照保存所用份量、换算和最终重量。继续使用既有缩放整数与舍入规则，修改份量不重算历史。

验收T29：总重、扣重、单位和精度有效；扣重大于总重、负数、无效份数被拒绝；可食重量为零时说明没有可记录的食用重量，不误存正热量。实际验证g/kg、多个扣除项、份量增删改、引用后修改、重启和备份恢复；汇总与保存的逐项结果一致。

## 4. I3：常用餐食模板

R21：模板包含名称、多项食物、各自重量或份数、可选餐次与备注，支持增删改查。一键带入形成可编辑草稿；用户选择日期、餐次，核对各项后统一保存。模板本身不产生摄入，不能重复点击生成重复批次。

实施设计、事务重复保护、结构3/备份3及跨结构回退检查见[常用餐食模板](常用餐食模板.md)。

保存整餐使用事务；有问题的食物或停用餐次须明确提示并要求重新选择，不能悄悄引用同名其他条目。模板保留引用和必要快照，模板、食物及份量更新不改写已保存历史。

验收T30：真实多项模板的创建、修改、带入、部分调整、取消、统一保存和重启回读通过；缺失食物、餐次停用、无效份量及实际写入失败均不得部分写入。历史日、连续列表、周/月统计所依赖的逐日合计正确；完整备份和回滚保护包含模板。

## I3a：录入设置与当日浏览（2026-10-23追加，尚未实施）

R27：新增设置页，初始默认采用“可食重量 × 每100克大卡 ÷ 100”；用户可改为直接输入大卡，设置重启后保留。仅影响新建摄入表单，编辑或复制保留原录入方式、数值和快照，切换设置不改变未保存草稿。

R28（按用户本次更正）：保存手动摄入时，检测个人热量库尚无对应资料的新食物，弹出提醒询问是否加入热量库；默认开启询问，可在设置中关闭。用户选择加入后，食物与摄入采用同一事务保存；选择不加入仍保存本次摄入，取消整个保存则均不写入。已有关联、同名同状态同热量或重复点击不得反复询问或新增，不覆盖同名但单位热量/状态不同的已有项。必须有合法的每100克热量；只有名称和本次总大卡、缺少可食重量或单位热量时，不猜算，询问中说明需要补充的资料并允许只保存摄入。加入来源标记为用户手动资料，保留状态及来源说明；关闭提醒后不询问、不自动写入个人库，日常离线。

R29：当日概况增加明显分隔的“按餐查看”方式，与完整明细/连续列表并存；早餐、午餐、晚餐独立标题、餐次小计和可滚动明细，加餐及自定义餐次独立展示，未记录与真实零保持区分。沿用餐次ID和历史名称，不能根据文字猜测并把自定义餐次归到三餐。压缩当日总热量卡片的高度，让摄入列表占据主要剩余空间；保存、修改、删除入口在最小窗口及高DPI下可达。

T36：真实设置保存、重启与新建默认方式；历史编辑/复制、未保存草稿不被改写，备份和回滚纳入设置。

T37：真实WPF确认与SQLite检查提醒开关、同意/拒绝/取消、资料不足、同名异状态/异热量、重复点击、写入故障事务撤销、重启回读；不编造单位热量或把摄入总量当作每100克热量。

T38：真实WPF和桌面核对三餐、加餐、自定义/停用餐次、空餐和零值，分组及当天总和与完整明细一致；增删改立即刷新，滚轮、键盘、最小窗口及四档缩放下明细和操作可达。实施前记录当日布局尺寸对比，验收列表空间改善。

## 5. I4：周/月统计

R22：按周、按月查看每天已记录摄入、已记录天数、已记录日平均及简单趋势。默认周一至周日，允许查看明确区间；未来日期不参与统计。未记录日期显示缺失，真实零值继续显示零；不推断某一天已完整记录，也不把缺失当零填入平均。

计算在Core完成，读取复用一次区间查询；WPF提供区间切换、图形与可读数值。优先利用现有组件绘制简单趋势，不为装饰增加依赖；只在有明确需求时选择成熟绘图库并固定版本。

验收T31：使用真实SQLite核对跨周、跨月、闰日、空区间、零摄入、缺失日与日合计；图形空缺和标签与数值一致。修改及删除记录后统计立即更新；最小窗口、键盘访问及高DPI检查通过。

## 6. I5：个人目标、身体测量与锻炼

R23：用户自行设置每日摄入目标及生效日期；记录体重kg、可选腰围cm和备注，支持增删改与简单趋势。目标调整保留历史生效区间，不套用新目标重写过去；未设目标、未测量均显示缺失。不得根据不完整的个人资料自动给出饮食处方或减重结果承诺。

R24：按日记录活动名称、时长、备注，以及可选的用户输入消耗大卡。运动与摄入分别显示，运动消耗不得自动抵扣摄入；不接入穿戴设备或在线估算服务。目标、测量及运动进入版本化数据和完整备份。

验收T32：目标生效日期、修改历史、重复日期处理规则明确；重量、腰围、精度和范围校验清楚，缺失与零不混淆；真实增删改、重启、备份恢复及历史目标比较通过。任何平滑或均值明确标注所用实际测量次数，不插入虚构测量。

验收T33：运动的时长与可选热量边界、修改、删除和重启回读通过；无论如何增删运动，摄入日合计及个人目标的摄入比较保持独立。完整备份回读与回滚演练保留全部新增数据类型。

## 7. I6：菜谱热量计算

R25：菜谱包含名称、食材、各自可食重量、制作说明、实际成品总重和份数。计算整道菜、每份及每100克大卡；按份或成品克数带入摄入草稿，由用户确认保存。成品重量由用户提供，不能假设水分变化、烹饪损耗或把骨重当成食用重量。

配方保存所用食物及营养快照；引用最新食物信息须明确更新。菜谱和食材后续修改不改历史摄入。Core集中处理计算与舍入，Infrastructure保存菜谱及版本化备份，Desktop复用食物和摄入选择流程。

验收T34：实际验证多食材求和、份数与成品重量、按份/按克引用及舍入一致性；无效成品重量、份数、缺失食材明确拒绝。菜谱修改、删除、食物变动、重启、完整备份恢复与跨版回退均验证，不把单项计算通过当作完整验收。

## 8. I7：自动备份及CSV/Excel导出

R26：保留现有手动完整备份和恢复；增加程序运行期间按设置自动生成的本机多份备份及轮换。默认当天首次成功写入后生成一份，此后有成功写入且距上份自动备份超过30分钟时再生成；备份失败不伪称已提交的记录保存失败，须单独明确提示。默认保留最近7份已验证可读的自动备份，并在升级、迁移、恢复前单独建立恢复点；恢复点不参与普通轮换。未成功生成可读新备份前不得删除最后可用备份，不新增系统后台计划任务。

提供所选区间的CSV与Excel（.xlsx）明细导出，包含日期、餐次、食物、重量、单位热量、摄入大卡、备注和来源；其他已实现数据类型按独立工作表导出。明确单位、时间格式及缺失值语义；导出是可阅读资料，完整恢复继续使用版本化备份。

使用成熟格式库生成CSV/.xlsx，实施前检查许可、兼容版本并更新依赖锁文件；无需用户安装Excel。CSV采用UTF-8 BOM，正确处理逗号、引号、换行和公式注入；文本字段安全转义不改变完整备份的原始数据。失败保留既有文件，覆盖导出需用户选择确认。

验收T35：实际验证自动触发、保留份数、备份可读、轮换及真实文件占用/不可写失败保护；独立测试库恢复后所有数据语义一致。CSV与Excel真实写出后由成熟读取库回读，核对中文、特殊字符、数值精度、缺失/零及公式样式文本。核对导出筛选范围、跨表关联、未安装Excel时运行、最小窗口操作与包内依赖。

## 9. 所有版本的共同验收

1. 编写功能前完善本版本数据模型、必要接口和迁移方案；沿用Core、Infrastructure、Desktop，不预建未使用的通用框架。
2. 运行新增业务、真实SQLite和相关WPF检查，再执行已有核心回归与实际桌面操作；数据使用独立目录，不能写入真实用户资料。不新增mock替代真实验证。
3. 新数据类型必须纳入完整备份、恢复、校验及回滚。兼容时实测旧版往返保留全部当前数据；不兼容时完整归档新版数据，明确旧恢复点和旧版无法展示的记录，再验证安全恢复及返回新版。旧版不得静默忽略并丢弃新字段或表。
4. 独立源码快照完成锁定还原、重建、测试与程序启动；核对锁文件、数据包和程序版本，完成自包含包启动与校验。不覆盖上一稳定包、源码、标签或Release。
