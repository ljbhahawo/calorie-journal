# 需求说明

用途：定义首个完整版本及后续迭代的产品范围和验收依据。首版实施依据1.0，2026-10-22；2026-10-23补充至R35千焦换算、直接模式切换与蛋白质。技术方案、交付方式及首批至少50项常见基础食物已获用户确认。决策状态见 [决策记录](决策记录.md)。

## 1. 目标与用户

在 Windows 11 上为单人提供持续可用的本机饮食热量记录工具。用户在吃完一项食物或事后补记时，快速记录日期、餐次和大卡，查看当天分餐汇总，并维护自己常吃的食物数据。界面使用中文。

用户明确要求：离线桌面应用；手动录入与内置食物库并存；分项记录；支持重量乘单位热量；食物库增删改查；具有足够的扩展性与可维护性；先完成规划再开发并持续记录软件生命周期。

## 3. 页面和主要操作流程

| 页面 | 信息和操作 |
|---|---|
| 每日记录 | 日期导航、当天合计、分餐列表和小计；新增、编辑、删除；显示已记录条数 |
| 录入窗口 | 日期、可选时间、餐次、食物搜索/手动方式、重量、单位热量、结果、备注；保存成功后可继续添加下一项 |
| 食物库 | 搜索、列表、来源、单位热量；新增、修改、删除；选择食物后进入录入窗口 |
| 历史记录 | 起止日期、每日已记录合计、记录条数；点击日期进入明细 |
| 设置与数据 | 餐次管理、备份、恢复、数据目录、软件与数据库版本、数据来源说明 |

录入流程：选日期和餐次 → 搜索具体状态的食物 → 输入重量 → 检查计算结果 → 保存。未找到条目时可直接手动录入，也可先新增食物再引用。

编辑流程：打开历史条目 → 加载保存时的快照 → 修改需要的字段 → 保存。食物库已变化时不自动套用新值，用户主动重新选择食物才使用新值。

食物维护流程：搜索 → 新建或编辑 → 校验 → 保存。删除前说明不会删除历史摄入；已删除条目退出可选列表，升级不能自动恢复用户已删除的条目。

## 4. 业务规则与边界

- 全部热量使用大卡（kcal）。重量支持 g 和 kg，统一换算为 g；单位热量以 kcal/100 g 显示和编辑。首版不自动把 mL、碗或个换算成克。
- 按重量计算：本项大卡 = 重量(g) × 每100克大卡 ÷ 100。业务采用十进制计算，每项结果按四舍五入保留一位小数；汇总对已保存的每项结果求和，确保列表和总数一致。
- 建议技术输入范围：直接热量 0–99,999.9 kcal；重量大于0且不超过100,000.0 g；单位热量 0–10,000.00 kcal/100 g。重量最多一位小数，单位热量最多两位；超范围、超精度或无效数字明确报错。这些是软件输入限制，不代表饮食目标。
- 名称去除首尾空白后必填且最多100字；备注最多1000字；餐次名最多30字，非空且去除首尾空白后唯一。相同名称的食物可以因品牌或加工状态不同而并存，新增时提示相似项但不擅自合并。
- 食物必须区分生重/熟重和来源描述；用户新增食物可注明品牌和标签来源。临时更改录入窗口中的单位热量，只影响本次摄入。
- 记账日期默认本机今天，可补记过去日期；未来日期拒绝并提示。本机午夜后新建条目使用新的今天；编辑和已打开的未保存表单不静默改日期。
- 空白日期显示“未记录”；实际保存了0 kcal条目才显示“已记录0大卡”。汇总代表已记录摄入，不推断记录是否完整；没有记录的日期不计算为真实零摄入。
- 餐次停用后历史仍可查看；若重命名餐次，历史保留当时名称。摄入可以显式改到另一餐次或日期。
- 防止同一次保存操作因连续点击产生重复记录；允许用户主动记录两次相同食物。取消编辑、切换日期或关闭未保存窗口时提示丢弃修改。
- 数据写入失败必须明确告知；不能显示保存成功或切换为空数据库掩盖故障。

## 5. 数据与非功能要求

数据包含：食物库、餐次、摄入快照、数据版本、必要设置；详见 [架构设计](architecture.md)。默认保存到当前 Windows 用户的本地应用数据目录；开发与测试使用项目独立目录。

| 方面 | 首版标准 |
|---|---|
| 隐私 | 正常使用完全离线，无遥测、账户和远程同步；日志不含食物摄入明细。数据库和导出备份采用普通本地文件，不宣称加密 |
| 稳定性 | 事务写入；备份恢复和迁移可验证；数据库不可用时提示具体故障；同一用户只运行一个写入实例 |
| 可维护性 | 界面、业务、数据访问分离；固定依赖版本；数据库、备份和食物库包分别版本化；需求和测试可对应 |
| 可用性 | 中文界面、明确单位、键盘焦点与Tab顺序；保存/取消可区分，删除和恢复有明确确认；窗口缩放和高DPI可用 |
| 性能 | 待测目标：本机发布版启动不超过3秒，普通保存/当日查询不超过300毫秒，实际内置库搜索不超过300毫秒；记录环境、样本数量与实际值 |
| 数据耐久性 | 已成功提交的记录重启后存在；备份回读后数据语义一致；升级保留数据且失败不破坏原库 |

## 6. 主要风险和待定项

1. 当前已整理并验证60项USDA SR Legacy基础食物，逐项来源、食物状态、数值和中文映射见 [食物数据方案](食物数据方案.md)。

3. 当前Windows界面、发布包独立启动及恢复已实际验证；150%系统DPI下已操作，其他显示环境及干净机器未验证，不能由当前结果推断全部环境兼容。
4. 首版范围已经确认；普通实现细节由开发助手自主决定并记录。重大范围或技术路线变化先更新本文件、设计和验收清单并取得必要确认，再进入相关实现。
5. 锻炼、减脂管理、菜谱及相关质量迭代已有用户授权，无需就该授权范围重复确认；平台、网络服务或付费资源等授权边界仍然适用。所有新版必须保留并验证回滚路径，不兼容数据回退时说明其备份时间点及影响。

用户要求优化页面后，1.2选择R13界面优化：统一四页视觉、固定保存区、清楚的空白提示，历史未记录日期以横线表示热量，实际零热量继续显示0.0。业务范围及数据格式保持不变，验收T23见版本记录。

1.3选择R14历史文字导入，范围与T24见[历史记录导入](历史记录导入.md)。用户已明确本版支持自由文字和从Excel复制的表格，直接文件识别后续另加。先预览核对，保留原文和不确定性，防止合计与明细重复计数，导入前备份且事务追加。

1.4选择R15日期导航修正与R16连续列表。拒绝未来日期应先于草稿确认，今天的“后一天”不可用；无效日期不丢弃草稿，有效日期切换仍保留确认。每日页面增加“单日 / 连续列表”切换，切换浏览方式不清空草稿。连续列表默认最近30天，按日期倒序包含每日合计、餐次与摄入明细，空白日显示未记录，真实零摄入显示0.0。支持滚轮浏览、区间查询、继续加载更早30天；最多连续366天，超出时调整查询区间。每天提供添加按钮，每条摄入提供修改、删除按钮，复用同页左侧完整录入表单与原有快照规则。保存或删除后同步当日、连续列表和历史合计；删除确认、未保存修改保护继续生效。数据库、备份格式和依赖保持兼容。

1.5选择R17多来源热量查询。用户已确认可选联网；提供USDA及TFDA两个官方参考目录，支持中文、简繁中文及英文搜索、来源筛选、每100克大卡、原名、加工状态及原始链接。选中结果带入新增食物表单，核对保存后才加入个人食物库，保留来源标识和版本。参考目录与个人食物库分开；仅明确点击联网更新时下载TFDA公开资料，失败可见且保留原目录，不上传查询词或个人记录。详细设计与T26见[热量资料查询](热量资料查询.md)。
