# 热量资料查询

用途：规定1.5.0的R17范围、数据处理、实施顺序和T26验收。状态：2026-10-22规划，2026-10-23正式源码、程序和回滚验收通过，实施及验证结果在[开发进度](progress.md)记录。

## 用户流程与范围

食物热量库 → 查找热量资料 → 输入食物名称并搜索 → 按来源查看热量和加工状态 → 查看原始网页或带入新增表单 → 核对名称与数值 → 保存食物。普通搜索不联网；“联网更新TFDA资料”只在用户点击时下载官方完整公开数据，再按当前关键词查询。关闭窗口取消下载。不同来源、不同状态的结果独立展示，不自动平均或合并。

程序附带两个只读参考目录，与用户常用食物库独立。USDA SR Legacy 2018-04从官方CSV能量字段1008生成完整有热量值的目录，已有60项中文映射沿用；其余保留英文原名，支持英文查询，不编造中文菜名。TFDA食品营养成分资料集从官方JSON取“熱量”且单位kcal、基准每100克的记录；不叠加“修正熱量”，不把缺失值当零。程序使用Windows简繁转换供检索和显示，保留原始名称。初始目录均能离线搜索，首版个人食物库仍为60项。

联网下载地址为[TFDA官方JSON压缩包](https://data.fda.gov.tw/data/opendata/export/20/json)，[资料说明及字段](https://data.gov.tw/dataset/8543)。官方提供机构为卫生福利部食品药物管理署；资料页标示每3月更新。资料获取时间单独显示，不将获取时间当成营养检测日期。来源链接没有逐项页面时明确使用官方资料集页面并显示整合编号。TFDA采用[政府资料开放授权条款第1版](https://data.gov.tw/license)，保留机构、资料集、获取版本及授权链接；USDA采用CC0。

## 模块及数据保护

- Core：参考目录、搜索结果、来源过滤、多词查询、转为新食物的规则；与SQLite及WPF无关。
- Infrastructure：读取版本化参考目录，Windows简繁转换；HttpClient下载、ZIP和JSON标准解析、范围与唯一性验证、完整新目录替换缓存。限制压缩下载大小及展开大小，流式读取营养行，不提取ZIP路径。
- Desktop：独立查询窗口、单次异步更新、取消、来源详情与明确错误；主窗口带入待保存的新食物，保留全部来源，复用原有保存、同名提醒及草稿保护。
- `data/lookup/`：可再分发的官方公开快照及来源元数据，生成脚本和原始档案SHA256可追溯。`lookup/`本机缓存不进入个人数据库、完整备份或Git；缓存损坏时明确提示并允许显式使用随包目录重新查询。

候选条目只有保存到个人食物库后才进入备份。新增FoodItem使用新ID并保留来源，已有摄入快照不变。数据库1、备份1和原60项食物包版本不变；1.4.0可读新增食物，忽略独立参考缓存。回滚演练须包含从两个来源保存的食物及其摄入。

## 阶段与T26验收

1. 核对官方资料及真实档案；记录字段、许可、单位、版本和生成规则；完成本设计。
2. 实现目录生成、简繁中文查询、来源筛选及来源保留；使用实际公开数据与真实SQLite测试。
3. 实现查询窗口、联网下载与取消、错误提示、原始链接、带入表单及草稿保护；执行真实WPF与缩放检查。
4. 实际访问官方数据，验证下载与缓存重读、离线查询、零值、缺失/重复/错误单位拒绝和失败保护。网络验证单独执行，不用伪造HTTP响应代替真实联网。
5. 核心回归、独立源码重建、自包含包启动、1.5.0→1.4.0→1.5.0及备份恢复通过后，保留旧版并交付；按既有授权提交、推送、附注标签和私有Release。

T26完成条件：两个来源有实际有效结果；中文/简繁/英文及来源筛选可用；显示正确单位和加工状态；带入不自动写库，保存后原名/来源ID/版本/链接和摄入快照重启、备份及回滚均保留；取消和下载失败不修改个人数据或旧缓存；窗口在小尺寸及100/125/150/200%布局缩放下关键操作可访问；全部既有回归通过。跨显示器DPI、另一台干净Windows及未来官方接口变动不由本机结果推断。
