# 录入设置与按餐浏览

用途：记录1.8.1的R27–R29设计、数据影响与T36–T38验收。状态：2026-10-23正式本地验收通过；1.8.0及更早版本完整保留，发布状态见[开发进度](progress.md)。

## 设置与录入

“设置与数据”增加默认录入方式，以及新手动食物的入库方式：每次询问、自动加入、不加入。默认按重量计算、每次询问。设置明确保存，重启保留；只影响后续新建及保存行为，不改写正在编辑的草稿、历史快照或复制时的录入方式。

只对未关联个人库且包含有效名称、状态、每100克热量的新手动重量记录考虑入库。按名称、状态和单位热量查重；已有相同资料不重复询问/添加，同名异状态或异热量保留独立资料。仅有总大卡时不推算单位热量，照常保存摄入并提示资料不足。自动加入也遵守此规则，不覆盖或复活用户删除的资料。

询问提供加入、不加入、取消本次保存三种结果。加入时新食物与摄入共同事务提交；拒绝时只保存摄入；取消保留草稿且不写库。真实写入故障不能留下孤立食物或部分摄入。重复点击复用原保存防护，事务内再次查重。新食物来源明确为用户手动资料，保留状态和来源说明。

## 当日页面

保留完整明细和连续列表，增加“按餐”浏览。早餐、午餐、晚餐、加餐及自定义餐次分别展示标题、分隔色条、小计和明细，空餐明确未记录。按餐次ID分组，保留历史名称，停用且当天仍有记录的餐次继续展示；不会把名称相似的自定义餐次猜成三餐。

总量卡片压缩为紧凑标题和一行合计，不展示重复餐次小计占据高度；日明细使用剩余主要空间。按餐明细可滚轮浏览，支持添加、修改、删除，复用既有左侧表单、确认和快照规则；保存后当日、按餐、连续列表与历史同步刷新。

## 数据保护与交付

数据库4、备份4在现有元数据中增加版本化录入设置，旧结构1–3迁移前保存对应旧版可读数据库/JSON及校验说明；设置随完整备份恢复。旧备份恢复采用明确默认设置；恢复前完整归档当前数据。1.8.0须拒绝写入结构4，返回1.8.0使用结构3恢复点，归档当前全部摄入、食物、模板、批次、份量和设置；返回1.8.1后恢复完整新版归档并逐项比较。
